# Local database (Windows)

Runs the app against a Postgres database on this machine instead of the hosted
Supabase project. The Vercel demo is unaffected: it never sees `.env.local`.

## How it fits together

```
browser ──▶ Vite dev server :8080 ──/rest/v1──▶ PostgREST 127.0.0.1:3001 ──▶ Postgres localhost:5432 (techoasis_sms)
```

- All app code reaches the database through `src/lib/db.ts`. `VITE_DB_PROVIDER`
  picks the backend (`supabase` by default, `local` here). To move to another
  database later, change that one module.
- The schema comes from `supabase/migrations`; `storage-shim.sql` stubs the
  Supabase-only `storage` schema so those files apply unchanged.
- `auth-shim.sql` stubs Supabase's `auth` schema (`auth.users`, `auth.uid()`),
  and `local-auth.sql` adds laptop sign-in: bcrypt passwords, signed session
  tokens, revocable sessions and a 5-attempts-per-15-minutes lock. PostgREST
  checks each token (`PGRST_JWT_SECRET`) and each session (`PGRST_DB_PRE_REQUEST`).
- Image uploads (school logo/banner) are kept inline as data URLs in local mode.

## Where things live

| What | Path |
| --- | --- |
| Postgres 17 binaries | `%LOCALAPPDATA%\TechOasis\pgsql` |
| PostgREST | `%LOCALAPPDATA%\TechOasis\postgrest` |
| Database files | `%LOCALAPPDATA%\TechOasis\pgdata` |
| Logs | `%LOCALAPPDATA%\TechOasis\postgres.log`, `postgrest.log` |
| Credentials | `.env.local` in the project root (git-ignored) |

`.env.local` holds `DATABASE_URL` (the `techoasis_app` login used by the app),
`DATABASE_ADMIN_URL` (the `postgres` superuser) and `LOCAL_JWT_SECRET` (signs
session tokens). All were generated by the scripts; never share them.

## Commands

| Command | Does |
| --- | --- |
| `npm run db:setup` | First-time setup (safe to re-run) |
| `npm run dev:local` | Start Postgres + PostgREST, then the dev server |
| `npm run db:start` / `npm run db:stop` | Start / stop Postgres + PostgREST |
| `npm run db:migrate` | Apply new files from `supabase/migrations` |
| `npm run db:create-school` | Create a school and its first administrator login (asks for the details) |
| `npm run db:test` | Run the database tests (tenant isolation, permissions, sign-in) |

Nothing runs as a Windows service; after a reboot run `npm run dev:local` again.

To point a local run back at hosted Supabase, set `VITE_DB_PROVIDER=supabase`
in `.env.local`.

## Upgrading to Phase 1 sign-in (once)

```
npm run db:stop
npm run db:setup          # adds the anon/authenticated roles; keeps your data
npm run db:create-school  # your school and your administrator login
npm run db:test
npm run dev:local
```

Then sign in at http://localhost:8080/admin. Existing people from before
Phase 1 are kept, moved into the first school, and shown as Invited; use
"New invitation link" in User Management to give each of them a login.
